# 浏览器使用日记 · 小米浏览器扩展程序

粉丝自制工具，**非小米官方发布**。Manifest V3，数据只保存在本机 `chrome.storage.local`，不读取完整网址、不上传任何内容。

## 发布信息（已定稿）

- **名称**：`浏览器使用日记`
- **描述**（提交时填写）：只在本机统计你访问过的站点停留时长，popup 展示今日柱状图与近 7 天趋势。不读取完整网址、不上传任何数据。
- **场景标签**：创意扩展程序
- **权限说明**：`storage` 保存统计；`tabs` 读取当前活动标签的站点域名；`alarms` 每分钟结算一次停留时长

## 功能

- 统计每个站点的**域名级**停留时长，按日期归档，保留最近 30 天
- popup 今日柱状图（Top 8 站点）+ 近 7 天趋势切换
- 今日总时长、站点数、时长格式化（秒 / 分 / 小时）
- 「清空今日数据」二次确认
- 不记录完整 URL、路径、标题、Cookie、历史记录；不联网

## 计时原理（符合官方能力边界）

- `tabs.onActivated` / `tabs.onUpdated` / `tabs.onRemoved` 监听当前标签切换，把上一段停留时长结算进当天数据
- `alarms` 每分钟结算一次，避免长时间停留不切换时漏记；alarm 不保证精确定时，但每次都用 `Date.now()` 实际时间差计算
- 每次结算都从 storage 读取当前状态并写回，**不依赖 Service Worker 内存常驻**；写入通过队列串行化，避免事件并发重复累加
- 浏览器重启时把残留的 `startedAt` 重置为当前时间，避免把关机时间算进停留时长
- 只用官方清单内的 `storage` / `tabs` / `alarms`；未使用 history、notifications、idle、downloads 等不采用或双端不一致的能力

### 兼容性取舍

- `chrome.storage` 统一使用 **callback** 形式（`background.js` / `popup.js`）：Promise 形式需要 Chrome 95+，国内浏览器内核版本参差（实测机型内核为 Chromium 70），callback 全版本可用
- CSS 不使用 `clamp()` / `min()` / `max()`（Chrome 79+）与 flex `gap`（Chrome 84+），尺寸改由 CSS 变量 + 媒体查询驱动；`env(safe-area-inset-*)` 用于刘海屏让位
- 图片与字体全部本地，无外链、无 `eval`、无 inline 事件，符合 §1 的脚本要求

## 安装与真机验收（必须你自己做）

1. 把 `browser-usage-diary.zip` 放到手机或 Pad 可选择的文件夹。
2. 打开**小米浏览器 → 扩展程序页 → 导入本地扩展文件**，选择该 ZIP（无需解压、不需要开发者模式）。
3. 启用扩展，正常浏览几个网站一段时间（至少几分钟），点击扩展入口查看今日柱状图。
4. 切换「近 7 天」、试「清空今日数据」二次确认；重开 popup、刷新页面、重启浏览器后确认数据保留。
5. 用真机重新录 ≤15 秒、≤5MB 的视频并截图，替换我给的演示素材后再提交。

> `demo.mp4` 与 `preview-*.png` 是桌面模拟数据生成的**效果演示素材**，不是小米浏览器真机截图。官方规范不接受桌面 Chrome 截图代替参赛验收。作品本身需要真实使用一会儿才会产生数据，真机录制时请提前积累一些访问记录。

## 已知限制

- 统计从扩展启用后开始；无法读取安装前的浏览历史（且规范禁止使用 history API）。
- 只存 `origin`（协议 + 主机），同一站点不同页面合并显示，这是隐私友好的设计取舍。
- alarms 不保证精确定时，极短时间内切换标签（<1 秒）的时长会被忽略。
- 未使用 `action.setBadgeText` 等不采用的能力；popup 按容器宽度布局，窄窗口改为单列。
- 提交后不支持更新：真机验证完成后再上传最终 ZIP、截图和视频（三者须对应同一版本 1.0.0）。
